name: Essential icon governance
description: Founder constraints for canonical icon reconciliation, artwork review and preservation of published documents
---

Treat the approved canonical inventory as the meaning of the existing Essential library, not permission to
reassign an older persistent id. Preserve existing saved-project references and appearance, including legacy
geometry that is no longer in default browsing. Keep BINHI Elements outside Essential reconciliation work.

**Why:** The user explicitly required one evolving library without duplicate catalogs or silent semantic
remapping, while preserving published sites and saved projects.

**How to apply:** Give different meanings distinct persistent identities. Keep compatibility resolution for
historical ids. Never infer the meaning of an old id from a newly assigned canonical number.

The20×20 optical area and1.5px stroke are review targets, not authorization to bulk-rescale existing content.
AI-assisted compositions/drawings need explicit founder artwork and authorship approval before release.

**Why:** The user made appearance preservation and founder approval release conditions; mechanically
valid vectors and nonblank raster checks do not establish semantic legibility or ownership clearance.

**How to apply:** Present unchanged/proposed visual comparisons, report actual implemented versus
approved counts, and keep deployment and merge approval separate from local test success.
